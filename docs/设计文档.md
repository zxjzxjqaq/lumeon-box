## 1. 产品定位

一句话：**一个轻量、克制、有高级动效的 Windows 桌面整理工具**——取 360 桌面助手「桌面格子」的核心价值，去掉捆绑、弹窗与臃肿，用现代设计语言重新做一遍。

三个支柱（按优先级排序，冲突时高者优先）：

1. **极低占用**——硬指标：空闲内存 ≤ 30MB、空闲 CPU 0%、安装包 ≤ 5MB、单进程、无浏览器内核、无服务（§8）。任何功能与它冲突时砍功能。
2. **审美与动效**——有一套成体系的「动效系统」（§7），而不是零散的过渡动画。
3. **克制**——只做桌面整理这一件事，明确不做的东西写进文档（§3.4）。

项目代号：**LumenBox（流明盒子）**，仅为占位，随时可换。

### 对标与差异

| | 360桌面助手 | 本产品 |
|---|---|---|
| 桌面格子整理 | ✅ 核心 | ✅ 核心，且分类规则开放可编辑 |
| 双击隐藏图标 | ✅ | ✅（实现方案见 §6.3） |
| 快速搜索/启动 | ✅ | ✅（P1，全局热键呼出，**不建全盘索引**） |
| 便签/小组件 | ✅ | ✅（P2） |
| 常驻内存 | ~100–200MB | **空闲 ≤ 30MB，交互峰值 ≤ 60MB** |
| 进程形态 | 多进程+服务+推广模块 | **单进程，无服务、无计划任务、无驱动** |
| 安装包/捆绑 | 大，带推广 | **≤ 5MB，零捆绑零广告** |

## 2. 目标用户与场景

- 用户：Windows 10 (19041+) / 11 用户，桌面文件常年堆积，想要「整洁但不折腾」。
- 核心场景：
  1. 桌面乱 → **一键整理** → 文件飞入分类格子（这是产品的「品牌瞬间」）。
  2. 新下载/新建的文件落桌面 → 自动提示归位（或自动归入格子，策略见 D4）。
  3. 临时离开/演示 → **双击桌面空白隐藏所有图标**，露出干净壁纸。
  4. 快速找文件/开应用 → `Ctrl+Space` 呼出搜索。
- 成功标准：装完一周后仍在开机自启名单里（留存）；整理动作 3 秒内完成且可撤销；任务管理器里的内存数字是产品口碑的一部分。

## 4. 技术选型（决策点 D1）

「极低占用」约束下，判断标准只有一条：**谁能在空闲时把内存压到 30MB 以下且 CPU 归零，谁才有资格**。浏览器内核路线（WebView2/Electron）存在结构性的内存下限（50MB+），首先出局。

### 4.1 候选对比

数据为公开常见值与同类桌面软件经验估算，M0 阶段用真实 Demo 复核（§9）。

| 方案 | 安装包 | 空闲内存 | 动效能力 | 开发效率 | 判定 |
|---|---|---|---|---|---|
| **C++ / Win32 + Direct2D + Windows.UI.Composition** ★推荐 | **2–5MB** | **15–35MB** | ★★★★★ 合成线程弹簧动画为系统原生能力 | ★★ 工期约为 Tauri 的 3 倍 | **唯一同时满足极低占用 + 顶级动效的路线** |
| Rust + Slint（femtovg/Skia 渲染，无 webview） | 5–15MB | 25–50MB | ★★★★ 声明式 UI，内置常用缓动 | ★★★★ | 备选 Plan A′：占用达标、开发快，但 Windows shell 集成走 FFI、生态年轻 |
| Tauri 2（Rust + WebView2） | 3–8MB | 50–90MB | ★★★★★ | ★★★★ | 降级为第三备选：动效与包体好，但 WebView2 内存下限不满足「极低」 |
| Qt 6 QML（动态链接，LGPL） | 15–40MB | 60–120MB | ★★★★ | ★★★★ | 内存不达标 |
| C# WPF / WinUI 3 | 自包含 60–150MB / 框架依赖 ~2MB | 80–150MB | ★★★★ | ★★★ | 内存不达标 |
| Flutter Desktop | ~20MB | ~100MB | ★★★★ | ★★★ | 内存不达标；shell 集成走 FFI |
| Electron | 80–150MB | 150–300MB | ★★★★★ | ★★★★★ | **结构性出局** |

### 4.2 推荐：C++ / Win32 + Direct2D + Windows.UI.Composition（D1）

理由：

1. **极低占用的唯一达标者**：纯原生窗口 + D2D 绘制 + 合成器动画，空闲内存 15–35MB，无动画时主线程阻塞在 `GetMessage`，CPU 恒为 0。没有内核、没有运行时、没有 GC。
2. **动效上限反而更高**：Windows.UI.Composition 的弹簧动画（`SpringVector2NaturalMotionAnimation`）、隐式动画、表达式动画**运行在系统合成线程**上——主线程零负担、掉帧风险低，这正是「科技感动效」与「低占用」不冲突的原因。这是 WebView 路线做不到的（Web 的 spring 全靠主线程 rAF 模拟）。
3. **贴桌/透明/钩子等 Win32 集成零成本**：这些功能在混合方案里都要跨语言桥接，原生路线就是直接调用。

代价与对策（诚实写出）：开发效率约为混合方案的 1/3。对策：
- C++23 + WinRT 智能指针 + 全部句柄 RAII 封装，禁止裸 new/裸句柄；
- UI 只覆盖「卡片、图标、文字、菜单」这几类控件，自绘面可控；
- **降级链写死**：M0 spike 若暴露产能问题，按 **C++/D2D → Rust+Slint → Tauri 2** 逐级降级，每级都复核内存预算（Slint 25–50MB 尚可接受，Tauri 50–90MB 仅在「极低」被放宽为「低于同类」时才可用）。决策在 M0 结束时锁死，之后不再摇摆。

## 5. 系统架构

```
┌────────────── 单进程 · UI 层（Direct2D 绘制 + Windows.UI.Composition 动画）──────────────┐
│  桌面格子层 desktop-layer   快速搜索 spotlight   便签   小组件   设置面板   托盘菜单       │
└─────────────────────────────▲───────────────────────────────▲─────────────────────────┘
                 进程内直接调用（无 IPC、无序列化）          事件回调（监听/钩子 → Post 到 UI 线程）
┌─────────────────────────────┴───────────────────────────────┴─────────────────────────┐
│                               核心层（C++23，零 UI 依赖，可独立单测）                     │
│  watcher        classifier      organizer        shell/win32          hotkey    config │
│  ReadDirectory  分类规则引擎     执行+撤销日志     贴桌/DWM/钩子          全局热键   JSON  │
│  ChangesW+debounce                                                                配置  │
│  indexer（WIC 图标缓存）   tray   single-instance   autostart                            │
└────────────────────────────────────────────────────────────────────────────────────────┘
```

设计原则：
- **单进程**：UI 线程、监听线程、钩子线程分离但同进程；UI 假死不影响后台整理，反之亦然。无 IPC 意味着无序列化开销——这也是「极低占用」的一部分。
- **核心层全部为纯 C++ 库，不依赖 UI，可独立单测**；UI 层崩溃由看门狗（同进程异常捕获）重建 UI 状态，核心数据无损。

### 5.1 模块职责（每个模块一句话说清）

| 模块 | 职责 | 关键依赖 |
|---|---|---|
| `watcher` | `ReadDirectoryChangesW` 监听桌面目录，500ms debounce 批量发事件；**只监听桌面，不扫全盘** | Win32 |
| `classifier` | 输入文件路径，输出建议分类。内置默认规则 + 用户自定义规则（扩展名/关键词/正则 → 目标格子） | 无 |
| `organizer` | 执行移动：优先 `IFileOperation`（原生支持回收站与系统级撤销）；冲突自动改名；每步写入 `journal.jsonl` 供撤销 | Shell |
| `shell/win32` | 贴桌挂靠（WorkerW）、DWM 毛玻璃、低级鼠标钩子（§6.3）、点击穿透、多屏 DPI | Win32/DWM |
| `hotkey` | 全局热键注册（Ctrl+Space 等），冲突时提示并允许改键 | Win32 |
| `config` | 配置/规则持久化，JSON；写盘前原子替换（tmp + rename） | 无 |
| `indexer` | 文件类型图标提取一次 → WIC 编码 PNG 缓存到本地；UI 只读缓存，不常驻 shell 句柄 | WIC/Shell |
| `tray` / `single-instance` / `autostart` | 托盘菜单；命名互斥体防多开；开机自启（HKCU Run 键，可关） | Win32 |

### 5.2 数据流（以「新文件落地」为例）

```
用户往桌面存文件
  → watcher 捕获（500ms debounce 合并，专用线程）
  → classifier 给出建议分类
  → PostMessage 到 UI 线程：file-landed {path, suggestion}
  → UI 在对应格子播放「呼吸光晕」+ 浮出提示条「收入 文档?」
  → 用户点「归位」（或全自动模式下直接触发）
  → organizer 移动 + 写 journal（后台线程）
  → PostMessage：file-moved → UI 播放 FLIP 飞入动画（§7 #1）
```

### 5.3 数据与目录

```
%APPDATA%\LumenBox\
  ├─ config.json        # 行为配置（自启、热键、自动整理策略…）
  ├─ rules.json         # 分类规则（默认规则首次运行时拷贝，允许用户改）
  ├─ journal.jsonl      # 整理操作日志（撤销依据，滚动清理 > 500 条）
  └─ icon-cache\        # 文件类型图标 PNG 缓存（上限 10MB）
```

## 6. 关键技术设计

### 6.1 贴桌模式（格子「长」在壁纸上）

- 主路径：向 Progman 发送 `0x052C` 消息触发系统生成 WorkerW，定位到 `SHELLDLL_DefView` 之后的那个 WorkerW，把我们的窗口 `SetParent` 过去——即 Wallpaper Engine 同款方案，窗口位于壁纸之上、图标之下。
- 降级路径：挂靠失败（部分壁纸引擎/系统组合）→ 自动切换「置底模式」：`HWND_BOTTOM` 置底 + 失焦自动沉底，功能等价，观感略差。两模式并存，设置里可手动指定。
- 搜索框、便签等交互型窗口仍是普通置顶窗，不参与贴桌。

### 6.2 透明与毛玻璃（逐级退化，任何一层失败都不白屏）

| 层 | Win11 | Win10 |
|---|---|---|
| 系统级 | `DwmSetWindowAttribute(DWMWA_SYSTEMBACKDROP_TYPE)` → Mica/Acrylic，由 DWM 合成器出模糊，**我们零 GPU 成本** | `SetWindowCompositionAttribute` 高斯模糊 |
| 应用级 | 卡片底色半透明渐变 + 1px 内发光描边 + 预烘焙微噪点贴图（D2D 位图笔刷，一次生成） | 同左（自身即可成立，系统级只是增强） |

Win10 上若需要卡片内实时模糊（CompositionBackdropBrush 不可用），降级为「预烘焙壁纸切片模糊」：仅在壁纸更换时重算一次。

### 6.3 双击隐藏桌面图标（决策点 D6 的技术面）

- 方案 A（推荐）：`WH_MOUSE_LL` 低级鼠标钩子 + 点击坐标命中测试（判定落在 Progman 空白处）→ 切换桌面图标可见性。响应快、体验与 360 一致。代价：低级钩子是杀软敏感点（见 §10）。
- 方案 B（降级）：不做钩子，用全局热键（如 `Ctrl+Alt+D`）或托盘开关切换图标显隐。零风险，体验略逊。
- 文档默认按 A 设计，M1 用开关在设置里允许切到 B；若你（D6）选 B，则砍掉钩子代码。

### 6.4 分类规则引擎

- 默认规则表（扩展名 → 类目）随安装内置，例如：`doc/docx/ppt/pptx/pdf/txt/md → 文档`；`zip/7z/rar → 压缩包`；`exe/msi → 安装包`；`.lnk → 桌面快捷方式，默认**不整理**（保持原位，符合直觉）。
- 用户规则优先于默认规则，支持：扩展名、文件名关键词、正则、指定目标格子。
- 规则变更即时生效，无需重启。

### 6.5 文件操作安全（整理类工具的命门）

1. 移动优先走 `IFileOperation`（同盘 rename 秒级，跨盘 copy+delete），系统回收站语义保留。
2. 冲突处理：目标重名 → 自动追加 `(2)`，**永不静默覆盖**。
3. 每步操作（src→dst）写 `journal.jsonl`；撤销 = 逆序回放；程序崩溃后重启可检测未完成事务并提示修复。
4. 桌面格子里的文件**只移动不复制不删除**，删除永远是用户显式动作且进回收站。

### 6.6 其他

- 高 DPI：per-monitor v2 aware；多显示器下格子按「虚拟桌面 × 显示器」锚定记忆位置。
- 单实例：命名互斥体，二次启动唤起已有实例。
- 更新器：v1 不做自动更新（克制），留接口。

## 7. 动效系统（本产品的灵魂，决策点 D3）

### 7.1 设计语言：「Aurora Glass（极光玻璃）」

- **底色**：深空蓝黑 `#0B0E14` 系玻璃卡面（`rgba(255,255,255,0.04–0.08)`）+ 系统 Acrylic 实时模糊，暗色为先（D3）。
- **主色**：极光渐变 青 Cyan `#22D3EE` → 靛 Indigo `#818CF8` → 紫 Violet `#C084FC`。**只用于 1px 描边、焦点环、进度与光效，禁止大面积色块**——科技感来自克制。
- **质感**：16px 圆角、1px 内发光描边（`rgba(255,255,255,0.12)`）、微噪点纹理、柔和多层阴影。
- **字体**：DirectWrite + 系统字体栈（Segoe UI Variable / 微软雅黑）；可选内嵌 MiSans（+3MB 包体）提升中文观感。

### 7.2 Motion 三原则

1. **弹簧优先**：所有位移用 spring（约 stiffness 210 / damping 22，允许 ≤3% 过冲），禁用 linear；入场类用 `cubic-bezier(0.22, 1, 0.36, 1)`。
2. **合成线程承载**：所有动画跑在 Windows.UI.Composition 合成线程上，主线程只在动画起始时提交参数；**空闲时 0 帧 0 GPU**（粒子失焦即暂停）。
3. **有层次的时间**：micro 120ms（悬停/按压）、standard 240ms（展开收起）、expressive 420ms（一键整理编排）；同组元素 stagger 20ms/个；**任何一组完整动画 ≤ 800ms**——动效是反馈，不是表演。

### 7.3 动效清单（场景 → 规格）

| # | 场景 | 规格 |
|---|---|---|
| 1 | 一键整理 | 图标 FLIP 飞入目标格子，逐个 20ms stagger，spring 弹入 + 落定微挤压（scale 0.96→1）；整场 ≤ 800ms |
| 2 | 格子出现/消失 | 模糊 8→0 + scale 0.94→1 + y +8→0，240ms easeOutQuint |
| 3 | 格子展开 | 高度 spring 展开，内部图标错落浮现（stagger 20ms） |
| 4 | 悬停卡片 | 3D tilt ≤ 6° 跟随鼠标（ExpressionAnimation 驱动，主线程零轮询）+ conic 流光描边旋转（2.4s/圈，仅悬停期间运行） |
| 5 | 拖拽磁吸 | 目标格子呼吸光晕（1.2s 周期）；距格心 < 24px 磁吸吸附 |
| 6 | 双击隐藏 | 全部图标以点击处为中心 radial mask 波纹扫过淡出，300ms；呼出反向 |
| 7 | 快速搜索呼出 | 从屏幕上 1/3 处 scale 0.96 + 背景暗化 + blur，180ms |
| 8 | 系统监控 | 环形光弧 + 数字滚动 |
| 9 | 空状态 | 3–5 粒光尘缓慢漂浮（合成线程 SpriteVisual 池，30fps，失焦暂停） |
| 10 | 品牌瞬间 | 首次启动 logo 粒子汇聚（≤ 1.2s，仅播放一次；预烘焙关键帧，不引入 Lottie 运行时） |

实现映射：弹簧/隐式/表达式动画全部使用 Windows.UI.Composition 原生动画（合成线程）；噪点、渐变、流光纹理预烘焙为贴图由 D2D 采样；系统尊重「减弱动态效果」辅助功能设置（设置内可覆盖）。

## 8. 性能预算（极低档硬指标，M0 起每版回归实测）

| 指标 | 预算 | 达成手段 |
|---|---|---|
| 安装包 | ≤ 5MB（单 exe 本体 + 卸载器） | 原生编译，无运行时、无内核、按需字体 |
| 冷启动到可交互 | ≤ 500ms（目标 300ms） | 无内核初始化；UI 首帧只渲染格子层，其余视图懒建窗口 |
| **空闲内存**（私有工作集） | **≤ 30MB**；交互峰值 ≤ 60MB | 单进程；图标走缓存不持句柄；贴图预烘焙常驻显存而非堆内存 |
| **空闲 CPU** | **0%**（无动画、无文件变更时） | 事件驱动 + `GetMessage` 阻塞等待，无任何轮询定时器 |
| 交互动画 | 60fps（p95 帧时间 ≤ 16ms） | 动画全部在合成线程；主线程动画期间禁用同步布局计算 |
| 磁盘占用 | 本体 + 缓存 ≤ 20MB | journal 滚动清理 500 条；图标缓存上限 10MB |
| 进程/服务形态 | **单进程**；无服务、无计划任务、无驱动、无浏览器内核 | — |

### 8.1 资源红线（任何功能不得越过，写在代码评审 checklist 里）

1. 失焦且无动画时，GPU 占用必须为 0（合成器静默，粒子暂停）。
2. 禁止常驻定时器快于 1Hz；一切行为事件驱动。
3. 不注入其他进程、不装驱动、不创建服务/计划任务、不引入浏览器内核。
4. 文件监听只监听桌面目录；搜索不建全盘索引（§3.2）。
5. 任何「为了动效更炫」而引入主线程逐帧回调的方案一律否决（改用合成线程能力实现）。

## 10. 风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| C++ 路线开发效率低、迭代慢 | **高** | M0 spike 3 天 timebox 实测产能；不达标走降级链 C++ → Rust+Slint → Tauri（§4.2）；UI 控件面收敛（卡片/图标/文字/菜单）控制自绘规模 |
| C++ 内存/句柄泄漏反噬「极低占用」口碑 | 中 | C++23 + WinRT 智能指针 + 句柄 RAII；阶段性 ASan/句柄数回归；§8 预算进入每版发布检查单 |
| 无签名 exe 被杀软误报（尤其用了低级钩子） | 中 | M4 争取代码签名；设置内提供「钩子模式/热键模式」开关；发布时附构建说明 |
| WorkerW 挂靠兼容性（壁纸引擎、系统更新） | 中 | §6.1 双模式自动降级；维护已知冲突清单 |
| 中文路径 / 特殊字符文件名 | 中 | 全链路 UTF-16（Win32 原生宽字符）；journal 序列化规范统一 |
| 老系统（Win10 < 19041 / Win7） | 低 | 明确声明最低支持 Win10 19041，安装器拦截提示 |

错误处理基调：任何单点失败（监听失效、移动失败、钩子注册失败）→ 静默降级 + 托盘一次性提示，**绝不弹窗打扰、绝不阻塞主流程**；`organizer` 失败即回滚该批操作。

测试策略：`classifier` / `organizer` / `config` 为纯 C++ 模块，单元测试覆盖（含中文路径、冲突、撤销回放）；`shell/win32` 以 M0 Demo 做人工验收矩阵（Win10 19041 / Win11 × 单屏/双屏 × 100%/150%/200% DPI）；每版发布前用任务管理器/Process Explorer 回归 §8 预算（空闲内存、空闲 CPU、句柄数、GDI 对象数）。
