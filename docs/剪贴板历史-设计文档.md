## 1. 功能定位

一句话：**一个事件驱动、本地闭环的剪贴板历史面板**——复制过的文字 / 图片 / 表格 / 文件自动记录（默认 100 条），`Ctrl+B` 全局呼出，每条带「快捷复制」按钮，一键取回。

与 LumenBox 三个支柱的关系：

1. **极低占用**：全程零轮询、零钩子、零注入。监听走系统消息 `WM_CLIPBOARDUPDATE`（§5.1），空闲 CPU 恒为 0；内存只常驻索引元数据（≤100 条 × ~1KB），图片按需加载。
2. **审美与动效**：面板复用 Aurora Glass 语言与 Spotlight 的呼出动效规格（§5.5）。
3. **克制**：只做「记录 → 查看 → 取回」闭环。不碰云剪贴板、不做片段管理器、不做富文本编辑（§2.3 明确不做）。

### 与系统自带 Win+V 的差异化

| | Windows 自带 Win+V | LumenBox 剪贴板历史 |
|---|---|---|
| 历史 | 系统云剪贴板，格式有限，可被组策略/清理工具关闭 | 本地文件级存储，随 LumenBox 常驻 |
| 表格 | 部分场景丢失格式 | **多格式条目**：文本 + HTML 一起存、一起回写，Excel/Word 粘贴保留表格结构 |
| 文件 | 不记录复制文件 | 记录复制的文件列表（CF_HDROP），一键重新复制 |
| 置顶 | 无 | 常用条目可置顶（钉住，不参与淘汰） |
| 搜索/过滤 | 无 | 按类型过滤（全部/文本/图片/文件） |
| 记录开关 | — | 托盘一键暂停/恢复，一键清空 |

## 2. 需求

### 2.1 功能需求（v1 范围）

| # | 需求 | 说明 |
|---|---|---|
| F1 | 自动记录 | 复制以下内容时自动记录：纯文本（CF_UNICODETEXT）、表格/富文本（HTML Format）、图片（PNG / CF_DIB / CF_DIBV5）、文件列表（CF_HDROP）。同一条目可同时含多种格式（如 Word 里复制=文本+HTML+图片） |
| F2 | 条数上限 | 默认 100 条，可配置 20–500；超限按 LRU 淘汰，**置顶条目永不淘汰** |
| F3 | 去重 | 内容与现存条目相同 → 移到顶部并刷新时间戳，不产生重复条目 |
| F4 | 全局热键 | `Ctrl+B` 呼出/隐藏面板（D7）；支持改键，冲突时托盘气泡提示（沿用现有热键失败处理模式） |
| F5 | 快捷复制 | 每条右侧「复制」按钮，点击即回写剪贴板并关闭面板；双击卡片等效；键盘 `Enter` 复制选中项 |
| F6 | 类型过滤 | 面板顶部 Tab：全部 / 文本 / 图片 / 文件 |
| F7 | 管理 | 单条删除（`Del` 或悬停删除钮）、一键清空（面板内二次确认）、暂停/恢复记录（托盘 + 面板开关） |
| F8 | 置顶 | 悬停「置顶」按钮，钉住条目排最前、不淘汰、不参与清空 |
| F9 | 持久化 | 重启后历史保留（含图片缩略图）；数据只在本地磁盘，绝不出网 |

### 2.2 非功能需求

- 空闲 CPU 0%、监听零轮询；记录动作（打开剪贴板+拷贝字节）单次 ≤ 5ms，肉眼无感。
- 常驻内存增量 ≤ 3MB（仅索引）；面板打开峰值 ≤ +20MB（按需加载位图，关闭即释放）。
- 磁盘占用有硬顶：blob 总量默认 ≤ 64MB（D8），超限按最旧非置顶淘汰。
- 单进程、无服务、无计划任务、无钩子、无注入（不越过母文档 §8.1 资源红线）。

### 2.3 明确不做（YAGNI，v1 写死）

云同步、片段收藏夹/分类文件夹、富文本编辑、OCR、剪贴板内容加密（v1 只做本地文件，随用户 Profile 保护）、复制后自动粘贴到原窗口（P2 备选，见 D10）、应用黑白名单（P2）。

## 4. 数据流（以「复制一张表格」为例）

```
用户在 Excel 复制区域
  → monitor 收到 WM_CLIPBOARDUPDATE（UI 线程，事件驱动）
  → GetClipboardSequenceNumber 变化校验 + 自写标志检查
  → OpenClipboard（失败重试 ≤5 次 ×10ms）→ EnumClipboardFormats
  → 按优先级采集：CF_HDROP? / "PNG"·CF_DIB·CF_DIBV5 / "HTML Format" / CF_UNICODETEXT
     GlobalLock → memcpy 字节到内存 → CloseClipboard（≤5ms）
  → 计算 FNV-1a 内容哈希 → 命中去重：store.MoveToTop()
     未命中：store.Prepend() → 条数/字节超限即淘汰（写侧同步、磁盘延迟）
  → PostMessage 给 UI：条目元数据（类型/预览/时间/来源 exe）
  → 后台线程（沿用 watcher 线程模式）：
     图片经 WIC 转 PNG + 生成 128px 缩略图 → blobs\ 写文件
     index.jsonl 追加一行（小文本内联，大内容只存文件引用）
  → 面板若正打开：新条目置顶浮现（复用动效 #2 规格，240ms）
```

## 5. 关键技术设计

### 5.1 监听：事件驱动，零轮询（红线合规）

- `AddClipboardFormatListener(hwnd)` 挂在 **message-only 窗口**上（与主窗口解耦，Panel 关闭不影响记录）。Win Vista+ 全系统自带，**不是钩子、不注入其他进程**——这是与低级鼠标钩子（§6.3）不同的低敏感 API，杀软误报风险低。
- 剪贴板数据必须在 `CloseClipboard()` 前读取：采集阶段只做 `GlobalLock + memcpy`（字节进内存），**编码/落盘全部移到后台线程**，保证单次采集 ≤5ms。
- 争用处理：`OpenClipboard` 失败（其他程序正占用）→ 重试 5 次 ×10ms，仍失败则放弃本条更新（下次内容变化会再来）。
- 延迟渲染（delayed rendering）：某些程序只登记格式不给数据；`GetClipboardData` 返回空 → 该格式静默跳过，条目按剩余格式组装；全空则丢弃。
- **自写抑制**：快捷复制回写剪贴板前置位 `g_selfWrite` 标志，`WM_CLIPBOARDUPDATE` 检查标志即忽略；同时叠加哈希校验（与队首相同不记录）双保险。
- 系统级忽略格式：检测到 `CF_CLIPBOARD_VIEWER_IGNORE`（KeePass 等密码管理器使用）→ 整条不记录（隐私默认行为，见 §5.7）。

### 5.2 多格式条目模型（表格的关键）

**一个逻辑条目 = 一次复制事件 = 多个格式载荷**。回写时全量还原，粘贴端按自己的能力取用（Excel 取 HTML → 表格结构保留；记事本取纯文本）。

| 类型判定（优先级从高到低） | 触发格式 | 存储载荷 |
|---|---|---|
| `files` | `CF_HDROP` | 文件路径列表（引用，不拷贝文件本体） |
| `image` | 注册格式 `"PNG"` / `CF_DIBV5` / `CF_DIB` | 统一转 PNG 落盘；DIB 自底向上/行对齐在转码时归一 |
| `html`（表格） | 注册格式 `"HTML Format"` | 原始 HTML 片段落盘 + 剥标签生成纯文本预览 |
| `text` | `CF_UNICODETEXT` | ≤4KB 内联进索引，>4KB 存 `.txt` blob |

- 同条目多格式并存：例如 Word 复制产生 `text + html`；截图工具产生 `image + text`（文件名）。条目 `type` 取**展示优先级**（files > image > html > text），载荷全存。
- 容量护栏（可配置）：单条文本 > 1MB → 截断存储并标记；单张图片解码后 > 32MB 或最长边 > 8192px → 拒收并托盘一次性气泡提示（沿用「静默降级 + 一次提示」基调）。

### 5.3 存储与淘汰（D8）

```
%APPDATA%\LumenBox\
  ├─ clipboard\
  │   ├─ index.jsonl        # 条目索引：一行一条（含内联小文本、blob 引用、置顶/时间/哈希/来源）
  │   ├─ blobs\<id>.png|.html|.txt
  │   └─ thumbs\<id>.png    # 128px 缩略图（面板列表用，按需生成）
```

- **索引写策略**：追加写为主（记录新条目、置顶、删除对应重写快照）；快照重写 = tmp + rename 原子替换（与 `config` 同模式）。启动时逐行读入，损坏行静默跳过（与 `journal` 同模式），blob 缺失的条目显示占位并可删。
- **淘汰**：`count > clipboardMaxEntries` 或 `blobBytes > 64MB` → 从最旧的非置顶条目开始淘汰，连带删 blob + 缩略图。置顶条目数量上限 10（防置顶塞爆）。
- `id`：`ts_base36 + 随机 4 字节` 十六进制，避免重启后碰撞。
- 来源应用：`GetClipboardOwner → QueryFullProcessImageName` 取 **exe 名**（如 `WINWORD.EXE`）显示在卡片角落；设置可关（§6）。

### 5.4 全局热键（D7）

- 默认 `Ctrl+B`（`MOD_CONTROL | MOD_NOREPEAT`，防长按重复）。注册 id=5。
- **已知代价（诚实写出）**：`RegisterHotKey` 是系统级拦截，注册后任何前台程序里的 `Ctrl+B`（编辑器加粗、IDE 侧栏）都会被 LumenBox 吃掉。缓解：
  1. 支持改键：`config.clipboardHotkey`（如改 `Ctrl+Alt+B` / `Ctrl+Shift+V`）；
  2. 注册失败（被占用）→ 托盘一次性气泡 + 自动尝试备选键，与现有热键处理完全一致；
  3. 拍板项 D7：接受 Ctrl+B 默认（体验最顺）vs 默认 Ctrl+Alt+B（零冲突）。**推荐保留 Ctrl+B**（与需求一致，改键兜底）。
- 面板呼出定位：跟随当前光标所在显示器的工作区顶部 1/3 处（多屏 DPI 用现有 per-monitor v2 约定）。

### 5.5 面板 UI（Aurora Glass）

```
┌────────────────────────────────────────────┐
│ ⌕过滤: [全部] [文本] [图片] [文件]   ⏸  🗑  │  头部 40px：Tab + 暂停/清空
├────────────────────────────────────────────┤
│ ▸ 今天 14:32 · WINWORD.EXE          [📋][📌][✕] │
│ │ 销售汇总表 ……（文本预览 2 行，HTML 条目加「表格」角标）│
├────────────────────────────────────────────┤
│ ▸ 今天 14:20 · SnippingTool.exe     [📋][✕]   │
│ │ [缩略图 128px] 1920×1080 PNG · 340KB      │
├────────────────────────────────────────────┤
│ 📌 置顶：qBittorrent.exe  3 个文件           │
└────────────────────────────────────────────┘
```

- **窗口形态**：完全复制 Spotlight 的工程模式——分层窗口 + `UpdateLayeredWindow` 整帧原子重绘、GDI+ 绘制、无系统擦除、无空闲定时器（光标闪烁定时器仅可见时运行）。宽度 560（同 Spotlight），最大高度工作区 70%，超出走**滚轮/`PgUp·PgDn` 滚动**（重绘整帧，模式同 Spotlight Refresh）。
- **快捷复制按钮**：每条卡片右侧常驻「📋 复制」主按钮（F5 的核心），悬停浮现 📌置顶 / ✕删除。点击复制 → 按钮变 ✓ 120ms → 面板 240ms 淡出关闭。双击卡片=复制并关闭；`Enter` 复制选中项；`Del` 删除选中项；`Esc` 关闭；`Tab` 切类型过滤。
- **动效**（全部走现有 DComp 基座，规格对齐母文档 §7.3）：呼出 = 动效 #7（scale 0.96→1 + 淡入，180ms）；新条目插入 = 动效 #2（240ms easeOutQuint）；复制成功反馈 = micro 120ms。**面板失焦即关闭，无动画时 0 帧 0 GPU**。
- 图片条目：列表显示缩略图；选中态在卡片右侧放大到 320px 预览（同帧重绘，不弹新窗）。
- 空状态：3 粒光尘漂浮（动效 #9 规格，失焦即停）。

### 5.6 回写（快捷复制的正确姿势）

- 回写 = `OpenClipboard → EmptyClipboard → SetClipboardData × N（按条目载荷逐格式还原）→ CloseClipboard`，全部在 UI 线程同步完成（小数据，≤2ms）。
- 文件条目：重建 `DROPFILES` 结构（双 null 结尾的宽字符路径表）设 `CF_HDROP`。
- 图片条目：直接设注册格式 `"PNG"` + `CF_DIB`（WIC 解码 PNG → 转 DIB），兼容老粘贴端。
- 换成系统剪贴板当前内容的语义：回写后**系统当前剪贴板=该条目**，用户随后可正常 `Ctrl+V`。
- 自动粘贴（复制后向前台窗口发送 Ctrl+V）：**P2，默认关**（D10）——模拟按键有侵入性，部分应用还会拦截。

### 5.7 隐私与安全（剪贴板类功能的必答题）

1. **数据不出本机**：无任何网络代码路径；存储在用户 Profile 下，随账户 ACL 保护。
2. **密码管理器豁免**：尊重 `CF_CLIPBOARD_VIEWER_IGNORE`（KeePass/1Password 标记），默认不记录。
3. **一键止损**：托盘「清空历史」+ 面板内清空（二次确认）；「暂停记录」开关，演示/输密码场景可先停。
4. **无钩子无注入**：仅使用文档化消息 API，降低杀软误报面（对比母文档 §6.3 的低级钩子风险，本功能显著更低）。
5. 来源 exe 名默认记录（方便辨认「刚才是谁复制的」），设置可关。

## 8. 测试与验收

### 8.1 单元测试（core_tests，Catch2）

## 10. 风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| 全局 Ctrl+B 抢占编辑器快捷键，用户体验反弹 | 中 | D7 拍板；改键配置 + 注册失败备选键 + 文档显著标注 |
| 剪贴板争用/延迟渲染导致丢条目 | 中 | 重试机制 + 允许跳过（下次更新自愈）；不做阻塞等待 |
| DIB→PNG 转码边界（自底向上、行对齐、16bpp 老格式） | 中 | WIC 统一转码；§8.2 用画图/Word/截图工具三源交叉验证 |
| 剪贴板监听被安全软件警告 | 低 | 消息 API 而非钩子/注入；README 说明数据本地闭环 |
| 图片落盘慢拖 UI | 低 | 采集与落盘线程分离（§4）；UI 只收元数据 |
| index.jsonl 与 blob 不一致（崩溃窗口） | 低 | 先写 blob 后追加索引；启动对账，孤儿 blob 定期清理 |

错误处理基调（沿用母文档）：任何单点失败（打开失败、转码失败、落盘失败）→ 静默降级 + 一次性托盘提示，绝不弹窗、绝不阻塞复制行为本身。
